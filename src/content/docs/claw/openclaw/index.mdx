OpenClaw 是一个自托管的多渠道 AI Gateway。它把模型、会话、工具、Skills、插件和消息渠道组织在一个长期运行的 Gateway 中。

这个专栏只保留两类内容：

- 能够按明确版本复现的使用和扩展方式；
- 来自真实故障、包含证据链和验证结果的排障记录。

## 当前版本的最短上手

安装最新稳定版本：

```bash
npm install -g openclaw@latest
openclaw --version
```

运行交互式配置并安装后台服务：

```bash
openclaw onboard --install-daemon
```

确认 Gateway：

```bash
openclaw gateway status
```

发起一次 Agent 请求：

```bash
openclaw agent --message "用三点总结当前工作区状态"
```

命令和配置会随版本演进。复制任何示例前，都应先核对：

```bash
openclaw --version
openclaw help
openclaw doctor
```

## Tool、Skill 和 Plugin 怎么分

| 能力 | 用途 |
|---|---|
| Tool | 让模型调用一个具体动作 |
| Skill | 教 Agent 如何完成一类任务 |
| Plugin | 向运行时注册 Tool、Hook、Channel、Provider、Service 或其他扩展 |
| Hook | 在明确生命周期事件发生时执行逻辑 |
| Slot | 替换 memory、context engine 等排他性核心能力 |

如果只是给 Agent 增加一套操作步骤，优先使用 Skill；如果只是增加一个可调用动作，优先使用 Tool；只有需要介入运行时生命周期或提供完整扩展包时，才使用 Plugin。
